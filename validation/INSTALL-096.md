# 0.9.6 图表脏边修复与安装验证

## 修复内容

- `project()` 返回的宽高是 PDF 本地单位。旧高清裁剪直接把它当像素，56×6 单位的标签在 4 倍渲染中仍只裁 56×6 像素。改为计算完整栅格尺寸并使用逆仿射映射，覆盖旋转标签。
- 高清页使用固定 PDF 空间分辨率，按真实页面面积限制像素预算；阅读器缩放不再误用另一缩放的缓存，渲染显式传入旋转角度。
- 对紧贴字形的 PDF/OCR 旧框增加最多 0.9 PDF 单位的显示边距，避开邻近标签（包括未翻译公式）和正文。扩大范围须通过保留图形结构的掩膜检测；检测未通过时仅使用原框。
- 显示边距和掩膜只存在于运行时缓存，不改写原文位置、译文、校订或历史。已有表格单元、图注和流程节点框保持原尺寸。
- 掩膜缓存键纳入邻近框，旧持久化掩膜可以先显示，再由修正后的高清掩膜替换。

## 验证过程

1. 回归先复现 56×6 与应有的 224×24 像素不符，再修正通过。
2. 首次安装只修坐标，宿主页面截图仍显示框外残余，未据此宣布修复完成。
3. 加入受限边距后再次安装，通过宿主 `inspect-page` 分别检查译文显示和仅擦除图；目标表 14 个显示标签中，13 个使用字形掩膜，1 个因相邻下标限制保留原框回退。
4. 用户反馈“好像可以了”，要求同步 GitHub。按当前版本归档，不继续改动显示方案。
5. 291 个 JavaScript 测试和 25 个 Python 测试通过；语法、XML、版本一致性及 `git diff --check` 通过。

宿主检查图仍存在个别细小彩色边缘。当前证据支持目标表显示改善，不代表所有复杂图形、缩放组合均完成视觉验收。原生去字后台已有的 `native-worker-rejected-source` 未在本轮修复；当前显示走浏览器掩膜路径。未发送真实翻译请求。
